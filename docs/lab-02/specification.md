# Lab 2 Sprint Engineering Specification

## 1. Sprint Goal
Build a Requester-facing application using a temporary Development Requester identity, allowing users to create tickets, attach files, and view their own tickets

## 2. Stakeholder Request Interpretation
The IT department needs a responsive interface for end-users to submit support requests (with attachments), view them in a "My Tickets" dashboard, and inspect ticket details. A temporary "Development Requester" selector acts as a simulated login for testing ownership.

## 3. Scope
### Included
- Development Requester selection mechanism.
- Create Ticket, My Tickets, and Ticket Detail screens (Requester view).
- Attachment lifecycle: upload, download, and soft-removal.
- Search, filtering, sorting, and pagination for the ticket list.
- Zen Green UI Theme and responsive design.

### Excluded
- Real authentication, login, passwords, and roles.
- IT Staff workflow (dashboard, queue, reassignment).
- Public Comments, Internal Notes, Actions Taken, and status changes beyond "New".

## 4. Functional Requirements
- **FR-01**: The system must allow users to select a Development Requester.
- **FR-02**: The user must be able to create a ticket and upload up to 5 attachments (max 5MB each).
- **FR-03**: The user must be able to view a paginated list of their own tickets, with search and filters.

## 5. Business Rules
- **BR-01**: The official Ticket Number is generated by the backend and must be unique.
- **BR-02**: A new Ticket begins with Current Status New.
- **BR-03**: Lab 2 uses a Development Requester selector instead of login (testing only).
- **BR-04**: Attachment removal is a soft-removal; removed files remain visible as metadata but cannot be downloaded.

## 6. UI Specification Summary
- Reference: `ui-spec.md`.
- Design system: Zen Green Theme (#006B3C primary, #0B7A46 secondary).
- Responsive rules: Desktop (>=992px), Tablet (768-991px), Mobile (<768px).

## 7. Data Changes
- **Models**: Ticket, Category, RelatedSystem, Attachment, DevelopmentRequester.
- **Relationships**: A Ticket belongs to one Requester, has one Category, one RelatedSystem, and many Attachments.

## 8. API Contract
- Reference: `api-spec.md`.

## 9. Acceptance Criteria
- **AC-01**: Given valid Ticket data, when the Requester submits the form, then one Ticket is saved and the official Ticket Number is displayed.
- **AC-02**: Given no Development Requester is selected, when the user attempts to open My Tickets, then the Requester Selection screen is shown.
- **AC-03**: Given Requester B is selected, when a Ticket belonging to Requester A is requested, then the Ticket data is not returned.

## 10. Definition of Done
- All required tests pass in the final main branch.
- Every acceptance criterion is linked to test evidence.
- Implemented screens conform to the Zen Green UI specification.
- README is updated and code is peer-reviewed.
